# 요원 선발 자동화 — Phase 1: 엑스파일 로그인 + 지원자 수집 설계

작성일: 2026-08-06

## 배경 및 목적

미닝에코 행사 운영 프로세스 자동화 프로젝트의 첫 착수 항목. 전체 로드맵(요원 선발 → 공고 템플릿 → 지원자 알림 → 임금 자동계산 → 플랫폼화) 중 "요원 선발 자동화"의 첫 단계로, 엑스파일 관리자 페이지에 로그인해 지원자 데이터를 수집하는 로직만 독립적으로 검증한다.

이후 단계(선발 엔진, 카카오 알림, 구글 시트 연동, 스케줄러, FastAPI)는 이 수집 로직을 기반으로 확장되며, 각각 별도 스펙으로 브레인스토밍한다.

## 전제 조건 (확인된 환경)

- 엑스파일은 자사 소유 사이트이나 외주 개발되어, 현재는 **관리자(어드민) 페이지 접근 권한만** 보유. 소스코드·서버 접근 불가.
- 관리자 페이지 로그인은 **아이디/비밀번호만** 요구 (2단계 인증·캡차 없음).
- 지원자 목록 컬럼: `no., 실명, 전화번호, 생년월일, 성별, 지원일시, 지원상태, 상태변경일시, 선택일정, 합격일정, 커스텀옵션1, 커스텀옵션2, 커스텀옵션3`
  - 커스텀옵션1 = 역할타입, 값은 `"A"`/`"B"`/`"C"` 텍스트
  - 커스텀옵션2 = 미닝에코 참여이력, 값은 숫자(횟수)
  - 커스텀옵션3 = 기타 (현재 파싱 대상 아님, 원본 값만 보존)
- 공고마다 별도 URL/페이지가 존재하며, 해당 공고의 A/B/C 타입별 필요인원도 같은 페이지에 표시됨.

## 범위

**포함**: 로그인 → 지정된 공고 URL 목록 순회 → 지원자 테이블 파싱 → 콘솔 출력 + JSON/CSV 저장.

**제외 (이후 단계로 이관)**: 신입/경력 비율 계산 및 조건 분기(선발 엔진), 카카오 알림, 구글 시트 연동, 스케줄 실행, 승인 처리, 진행 중 공고 자동 발견.

## 아키텍처

독립 실행 가능한 단일 Python 스크립트로 구성한다. FastAPI/스케줄러는 이후 단계에서 이 로직을 감싸는 형태로 확장한다.

```
config(.env) → 로그인(Playwright) → 공고 페이지별 순회 → 테이블 파싱 → 저장(JSON/CSV) + 터미널 출력
```

## 컴포넌트

| 모듈 | 역할 |
|---|---|
| `config.py` | `.env`에서 엑스파일 계정정보, 대상 공고 URL 목록 로드 |
| `xfile_client.py` | Playwright로 로그인 및 공고 페이지 이동 담당 |
| `applicant_parser.py` | 지원자 테이블을 구조화된 데이터로 변환. 커스텀옵션1→역할타입, 커스텀옵션2→참여이력(숫자)로 명시적 매핑 |
| `output.py` | 결과를 터미널 출력 + JSON/CSV 파일로 저장 |
| `main.py` | 전체 흐름 진입점 |

## 결정 사항 (승인됨)

- **로그인 방식**: 매 실행마다 새로 로그인한다 (세션 저장/재사용 방식 대신). 로그인이 아이디/비밀번호만으로 단순하여 매번 로그인해도 부담이 적고, 세션 만료로 인한 디버깅 부담을 없앤다.
- **공고 대상 지정**: `.env`/설정 파일에 테스트할 공고 URL을 직접 나열한다. 진행 중인 공고를 자동으로 스캔하는 기능은 5단계(스케줄러 연결) 시점으로 미룬다.

## 데이터 흐름

1. `main.py`가 `config.py`를 통해 계정정보와 공고 URL 목록을 로드한다.
2. `xfile_client.py`가 로그인을 수행한다. 실패 시 즉시 에러 메시지와 함께 종료한다.
3. 설정된 공고 URL 목록을 순회하며 각 페이지의 지원자 테이블을 읽는다.
4. `applicant_parser.py`가 원본 테이블 행을 구조화된 데이터(역할타입, 참여이력 숫자 파싱 포함)로 변환한다.
5. `output.py`가 결과를 콘솔에 출력하고 `output/YYYYMMDD_HHMM.json`, `.csv`로 저장한다.

## 에러 처리

- **로그인 실패** (잘못된 계정정보, 페이지 구조 변경 등): 명확한 에러 메시지와 함께 즉시 종료. 알림 연동은 3단계에서 추가되므로 1단계는 콘솔 에러로 충분하다.
- **공고 페이지 접근 실패** (404, URL 오류 등): 해당 공고만 건너뛰고 나머지는 계속 진행하며, 스킵된 공고 목록을 로그로 남긴다.
- **행 단위 파싱 실패** (예상과 다른 값 형식 등): 해당 행만 스킵하고 경고 로그를 남긴 뒤 전체 실행은 계속한다.

## 테스트 전략

- `applicant_parser.py`는 저장해둔 HTML 스냅샷(fixture)을 이용한 단위 테스트로 검증한다. 실제 사이트 접근 없이도 파싱 로직을 반복 검증할 수 있다.
- 로그인·페이지 이동(`xfile_client.py`)은 실제 엑스파일 관리자 페이지를 대상으로 한 수동 통합 테스트로 확인한다 (자동 CI에는 포함하지 않음, 계정정보 노출 위험 및 실사이트 의존 때문).

## 보안/설정 관리

- 엑스파일 계정정보(아이디/비밀번호)는 `.env`에만 저장하고 하드코딩하지 않는다. `.env`는 `.gitignore`에 포함해 커밋 대상에서 제외한다.
