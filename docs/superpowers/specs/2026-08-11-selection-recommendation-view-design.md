# 선발 추천 보기 기능 설계

## 목적/범위

지원자 데이터 중 아직 결정되지 않은("대기" 상태) 지원자만 골라, 선택일정이 같은 사람끼리 그룹으로 묶어 보여주는 기능을 기존 결과 보기 화면(`view.py`)에 추가한다.

**이 기능은 100% 참고용이다.** 실제 승인/거절 등 어떤 액션도 수행하지 않으며, 최종 결정은 사람이 엑스파일 사이트에서 직접 한다. 화면에 클릭 가능한 요소는 필터/토글/검색뿐이고, 엑스파일 사이트로의 네비게이션이나 폼 제출은 전혀 없다.

**배포 범위:** 기존과 동일하게 완전히 로컬 실행이다. 서버 없음, 외부 접근 가능한 URL 없음 — 로컬 JSON 결과 파일을 읽어 로컬 HTML 파일을 생성하고 브라우저로 여는 방식 그대로 유지한다.

## 배경 (브레인스토밍에서 확인된 제약)

- 참여횟수(`participation_count`)는 미닝에코/엑스파일 내부 참여 이력만 반영하고, 다른 곳에서의 경력은 전혀 담지 못한다. 잘못된 우선순위를 자동으로 부여할 위험이 있어 **추천/그룹 로직에서 제외**하고, 기존처럼 표시 컬럼(참고용)으로만 유지한다.
- 지원상태 "대기"가 실사이트에서 확인된 미확정 상태값이다 (다른 상태값: "승인됨", "취소됨" 등 기존 확인됨).

## 데이터/로직

- **필터:** `status == "대기"`인 지원자만 대상으로 한다.
- **그룹핑 키:** `selected_schedule`. 값이 비어있으면 "미지정" 그룹으로 묶는다.
- **그룹 내 정렬:** `applied_at` 오름차순 (선착순). 참여횟수 등 다른 기준으로 순위를 매기지 않는다 — 지원 순서가 자동 로직이 왜곡 없이 적용할 수 있는 유일하게 객관적인 기준이기 때문.
- 그룹 내 표시 컬럼은 기존 표(이름/전화번호/공고명/역할타입/참여횟수/지원상태/지원일시)와 동일하게 유지한다.

## UI 통합

- 새 화면이나 새 명령어를 만들지 않고, 기존 `view.html`에 "추천 보기" 토글을 추가한다.
- 기본 화면(전체 목록 + 공고 필터 + 검색)은 그대로 유지되고, 토글을 누르면 위 필터+그룹 결과가 일정별 섹션으로 나뉘어 표시된다.
- 상단에 "이 목록은 참고용이며, 실제 승인/거절은 엑스파일에서 직접 진행하세요"라는 안내 문구를 고정 표시한다.
- 대기 상태 지원자가 한 명도 없으면 "현재 대기 중인 지원자가 없습니다" 안내를 보여준다.

## 안전장치

- 순수 정적 HTML/클라이언트 사이드 JS로 구현 — 서버 요청, 외부 네트워크 호출, 엑스파일 사이트로의 어떤 폼 제출/네비게이션도 없음 (기존 `view.py` 아키텍처와 동일).
- 기존 `_safe_json` 이스케이프 방식을 그대로 재사용해 stored-XSS 위험을 방지한다.

## 테스트 계획

- 그룹핑/필터 순수 함수 단위 테스트: "대기" 외 상태 제외 확인, 동일 일정 그룹핑 확인, 빈 일정 "미지정" 그룹 확인, 그룹 내 지원일시 오름차순 정렬 확인.
- 렌더링 테스트: 대기 지원자 없을 때 안내 문구 렌더링, 참여횟수 컬럼이 그룹 뷰에도 표시되는지 확인, 참여횟수가 정렬/필터에 영향 주지 않는지 확인(회귀 방지).
- 기존 view.py 테스트(공고 필터, 검색, XSS 이스케이프)는 그대로 유지되어야 한다 — 회귀 없음을 확인.
